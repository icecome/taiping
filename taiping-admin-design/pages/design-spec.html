1整体布局规划

1.1 布局框架

后台采用经典的双栏 Grid 布局：左侧固定宽度侧边栏（240px）+ 右侧弹性内容区（1fr），整体高度撑满视口（h-screen），形成沉浸式管理界面。

/* Layout grid */
grid-template-columns: 240px 1fr;
grid-template-rows:    100vh;
sidebar  → 固定 240px，不可缩放
content  → 弹性 1fr，overflow-y: auto

1.2 侧边栏结构

侧边栏自上而下分为三个区域，各区域职责清晰、互不干扰：

  • 顶部（Logo + 搜索）：品牌标识与全局搜索入口，高度 52px，与顶栏对齐
  • 中部（导航分组）：可滚动区域，按模块分组排列导航项，支持折叠/展开
  • 底部（用户信息）：头像、昵称、角色，点击展开下拉菜单（个人设置/退出登录）

1.3 内容区域

内容区为右侧弹性栏，内部最大宽度限制为 1024px，水平居中。内边距 24px（p-6），纵向可滚动。每个页面顶部为页面标题 + 操作按钮区，下方为功能内容。

content-max-width: 1024px

overflow-y:         auto

1.5 信息层级

信息架构采用三级层级模型，确保用户在任意位置都能感知当前所处的层级位置：

Level 1 (模块)   → 内容 / 界面 / 系统
Level 2 (页面)   → 文章列表 / 编辑器 / 分类管理 ...
Level 3 (操作)   → 新建 / 编辑 / 删除 / 发布 / 批量操作

1.6 响应式适配

侧边栏在不同屏幕尺寸下采用不同的展现策略：

  • 平板（768px - 1199px）：侧边栏收缩为 64px 图标模式，仅显示图标，hover 显示 tooltip
  • 移动端（<768px）：侧边栏转为抽屉模式，默认隐藏，点击汉堡按钮滑入

3功能模块划分

3.1 文章管理

文章管理是后台核心模块，包含列表视图与编辑视图两个主界面，以及完整的发布流程与批量操作能力。

列表视图

  • 表格：展示标题、分类、标签、状态、更新时间、操作列，支持行 hover 高亮
  • 筛选器：顶部筛选栏，支持按状态（草稿/已发布/已删除）、分类、关键词筛选
  • 分页：底部翻页器，支持页码跳转与每页条数选择（10/20/50）

编辑视图

  • 标题区：大输入框，支持实时字数统计
  • 编辑器：Markdown 编辑器，支持预览模式切换与全屏编辑
  • 元数据侧栏：分类选择、标签添加、摘要、封面图、URL slug、发布时间

批量操作

  • 勾选多篇文章后，底部出现批量操作栏：批量发布、批量移至分类、批量删除
  • 危险操作（批量删除）需二次确认弹窗

3.2 分类管理

分类与标签共用一个管理界面，通过顶部 Tab 切换。

  • Tab 切换器：分类 / 标签 两个标签页，切换时保留各自的筛选与分页状态
  • 新增表单：名称、slug（自动生成）、父级分类（树形下拉）、描述
  • 拖拽排序：分类列表支持拖拽调整层级与排序顺序，拖拽时显示占位线
  • CRUD 操作：每行支持内联编辑、删除（带关联文章数提示）

3.3 标签管理

标签管理与分类管理界面一致，额外支持标签云展示模式：

  • 标签云：以词云形式展示所有标签，字号映射使用次数，点击进入该标签的文章列表
  • 合并标签：支持将多个标签合并为一个，迁移关联文章

3.4 评论管理

评论管理以状态分组展示，支持快速审核与批量操作。

  • 状态标签页：待审核 / 已通过 / 垃圾评论，切换时显示各状态计数
  • 评论卡片：展示评论者头像、昵称、邮箱、评论内容、所属文章、时间
  • 快速操作：每张卡片支持通过、加精、标为垃圾、删除四个快捷按钮

4响应式设计

后台界面需适配桌面、平板、移动端三种场景，各断点下的布局策略如下：

4.1 桌面端（≥ 1200px）

  • 侧边栏完整展开 240px，显示图标 + 文字标签
  • 统计卡片网格 4 列排列
  • 数据表格展示全部列，无横向滚动
  • 编辑器双栏布局（编辑区 + 元数据侧栏并排）

4.2 平板端（768px - 1199px）

  • 侧边栏收缩为 64px，仅显示图标，hover 显示 tooltip 提示文字
  • 统计卡片网格 2 列排列
  • 表格隐藏次要列（如标签、更新时间），保留核心信息列
  • 编辑器元数据侧栏折叠为底部抽屉或折叠面板

4.3 移动端（< 768px）

  • 侧边栏转为抽屉模式，默认隐藏，点击左上角汉堡按钮滑入，带遮罩层
  • 统计卡片单列堆叠展示
  • 表格转为卡片列表模式，每条记录以卡片形式纵向排列
  • 底部固定操作栏（批量发布/删除），替代表格内的行内操作

5交互体验优化

5.1 表单交互

表单是后台使用频率最高的交互载体，需在输入效率与错误预防两方面做到细致：

  • 行内校验：输入失焦时实时校验，错误信息显示在字段下方，红色边框 + 提示文字
  • 自动填充：填写标题时自动生成 URL slug，支持手动覆盖
  • 错误提示：错误提示位于字段正下方，字号 xs，颜色 error，不使用弹窗打断流程
  • 字数统计：标题、摘要等限长字段显示「当前字数 / 上限」计数器
标题不能为空（至少 5 字） 8 / 100
由标题自动生成，可手动修改

5.2 数据展示

列表数据的展示需兼顾信息密度与浏览效率：

  • 表格/列表切换：右上角提供表格视图与卡片列表视图的切换按钮，记忆用户偏好
  • 粘性表头：表格滚动时表头固定在顶部（sticky），始终可见列名
  • 可排序列：点击列头切换升序/降序，排序图标随状态变化
  • 分页器：底部分页器支持页码跳转，右侧提供每页条数下拉选择器（10/20/50）

5.3 搜索与筛选

搜索与筛选是列表页的核心导航能力，需做到即时响应且可组合使用：

  • 关键词搜索：输入框带 debounce（300ms），避免高频请求，回车立即触发
  • 多条件筛选：支持状态 + 分类 + 日期范围的组合筛选，筛选条件以标签形式展示在列表上方
  • 保存筛选：常用筛选组合可保存为快捷筛选，下次一键应用

5.4 批量操作

批量操作用于提升管理效率，交互流程如下：

  • 选择机制：每行首列为 Checkbox，支持单选与跨页选择
  • 全选：表头 Checkbox 支持全选当前页，可选「选择全部 N 条」
  • 操作栏：选中后底部浮出批量操作栏，显示已选数量与可用操作
  • 确认弹窗：危险操作（删除）弹出确认对话框，显示影响范围
已选择 5 篇文章

5.5 加载状态

加载状态需在不同场景下给用户明确的「正在处理」信号：

  • 骨架屏：首次加载列表时显示骨架屏（灰色占位条 + 闪烁动画），而非空白页
  • 旋转遮罩：按钮提交、表格刷新时叠加半透明遮罩 + 居中 spinner
  • 渐进加载：长列表支持滚动到底部自动加载下一页（infinite scroll），底部显示加载指示器

5.6 错误处理

错误处理需在视觉上明确区分，并提供恢复路径：

  • 错误边界：页面级错误由 Error Boundary 捕获，展示错误插图 + 错误摘要
  • 重试按钮：网络请求失败时展示空状态卡片，内含「重试」按钮
  • 空状态：无数据时展示空状态插图 + 引导文案 + 新建按钮，而非空白表格

5.7 通知提示

操作结果通过 Toast 通知反馈，出现在屏幕右上角，不阻断操作流：

  • 成功（绿色）：操作完成后显示，3 秒后自动消失
  • 错误（红色）：操作失败时显示，需手动关闭，确保用户看到错误信息
  • 信息（蓝色）：中性提示（如「正在后台处理」），3 秒后自动消失
