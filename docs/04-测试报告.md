## 4. 性能测试

命令：`node scripts/bench.mjs`（13 个有效样本，丢弃首次预热）

方法说明：并发压测在这个部署形态下意义有限——瓶颈是单次请求的 D1/KV 往返次数与渲染开销，而不是调度。因此统计单请求串行延迟的 min/avg/p95。

**匿名访问（页面缓存生效路径）**，模式：缓存命中

| 路径 | 最小 | 平均 | P95 |
| --- | --- | --- | --- |
| 首页 `/` | 17.1 ms | 19.3 ms | 22.2 ms |
| 文章页 `/post/:slug` | 16.6 ms | 17.9 ms | 20.2 ms |
| 归档 `/archive` | 28.8 ms | 31.9 ms | 37.2 ms |
| 分类页 `/category/tech` | 27.1 ms | 29.8 ms | 39.1 ms |
| 搜索 `/search?q=…` | 24.3 ms | 26.9 ms | 31.2 ms |
| RSS `/rss.xml` | 13.5 ms | 14.9 ms | 16.3 ms |
| sitemap `/sitemap.xml` | 14.3 ms | 15.3 ms | 17.0 ms |
| API `/api/health` | 7.3 ms | 8.4 ms | 12.2 ms |

**匿名访问**，模式：每轮 bump 缓存版本后再请求（缓存未命中）

| 路径 | 最小 | 平均 | P95 |
| --- | --- | --- | --- |
| 首页 `/` | 32.4 ms | 40.5 ms | 53.1 ms |
| 文章页 `/post/:slug` | 37.7 ms | 45.3 ms | 56.3 ms |
| 归档 `/archive` | 22.2 ms | 28.0 ms | 36.9 ms |
| 分类页 `/category/tech` | 19.7 ms | 29.1 ms | 35.3 ms |
| 搜索 `/search?q=…` | 18.1 ms | 24.3 ms | 29.8 ms |
| RSS `/rss.xml` | 11.3 ms | 15.9 ms | 32.6 ms |
| sitemap `/sitemap.xml` | 11.3 ms | 14.5 ms | 20.4 ms |
| API `/api/health` | 5.8 ms | 8.3 ms | 10.7 ms |

**读取结论**

1. 页面缓存对两条被缓存的路径有效：首页 40.5 → 19.3 ms（约 2.1×），文章页 45.3 → 17.9 ms（约 2.5×）。
2. 未被缓存的路径（归档、分类、搜索）稳定在 24–32 ms，主要成本是 D1 的多次往返；这些页面的查询已全部下推到 SQL 分页，没有全表拉取。
3. `api/health` 的 8 ms 是本地 wrangler 的基线开销（miniflare 的进程间通信），真实边缘环境下这一层不存在。
4. 缓存未命中的数字里包含了每轮一次 `DELETE /api/settings/cache` 带来的 KV 写入竞争，真实冷启动会略低于表中数值。

**包体积与启动**

| 项 | 数值 |
| --- | --- |
| Worker 脚本（不含静态资源） | 1 452 KiB（gzip 269 KiB） |
| 后台 SPA 产物 | `index-*.js` 645 KB + `index-*.css` 31 KB + `index.html` 0.6 KB |
| 一次部署的总上传量 | 2 509 KiB（gzip 524 KiB） |
| 口令哈希单次耗时 | 约 40 ms（100k 次 PBKDF2-HMAC-SHA256） |
| 单元测试全量 | 1.0 s |
| 集成测试全量 | 6.0 s |

包体积能压到 1.45 MB（Worker 部分）的主要原因是前台不引入 React（见 [ADR 0004](./adr/0004-前台服务端JSX与后台SPA.md)）。占体积的前三位是 highlight.js 的语言定义、`@hono/zod-openapi` 依赖的 zod、drizzle 的查询构造器。后台 SPA 的 645 KB 只在访问 `/admin` 时加载，不影响前台访客。

## 7. 缺陷与已知限制

测试过程中发现并已修复的问题：

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 所有内容详情页 500 | 把 `Date` 绑进 `sql\`\`` 模板，D1 只接受 string/number/null/ArrayBuffer | 换成毫秒时间戳（`site/data.ts`） |
| `/api/nope` 返回前台 HTML 404 | 前台 catch-all 先于 404 处理器匹配 | 在 `app.ts` 里为 `/api/*` 与 `/media/*` 注册显式兜底 |
| 文章标题锚点是中文 | 标题 id 用了原字符 | 改用与内容 slug 相同的拼音规则 |
| 原生 HTML 未被转义 | marked 默认透传 HTML | 覆盖 `html` 渲染器为转义 |
| 后台逻辑与页面标题重复站点名 | 路由 meta 里已拼了站点名，layout 又拼一次 | meta 只给页面自己的标题 |
| 集成测试第二个用例 setup 返回 409 | 测试池的隔离存储按文件生效，同文件内数据累积 | `resetState()` 显式清表 |

保留的已知限制（都是有意取舍，不是缺陷）：

| 限制 | 理由 |
| --- | --- |
| 正文不能写原生 HTML | 换取「服务端不需要消毒库」，见 [ADR 0002](./adr/0002-内容安全的边界.md) |
| 缓存只能全站失效，不支持按 URL 精确失效 | 换取实现简单，见 [ADR 0001](./adr/0001-发布模型不建快照表.md) |
| 换主题/插件需要重新部署 | 不引入运行时沙箱，见 [ADR 0003](./adr/0003-插件与主题编译进-Worker.md) |
| CSP 保留 `unsafe-inline` | 前台主题与后台 SPA 各有一处必要的内联脚本，见 [ADR 0005](./adr/0005-CSP保留unsafe-inline.md) |
| 密码保护内容的解锁 cookie 无状态 | 内容改密码后旧 cookie 自然失效，不需要失效表 |
| 会话解析结果有 30 秒 KV 缓存 | 省去每请求一次角色查询；改密/停用/改角色走批量吊销路径，不受缓存影响 |
