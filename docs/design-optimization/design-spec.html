太平后台设计规范

本页是《B 端设计优化方案》§5 的可视化呈现。所有取值即目标规范，可直接对照实施。 设计基准来自行业规范调研（Ant Design / Carbon / NN/g）的独立推导，非继承自现有代码。

01 · 设计立场

这个产品的视觉辨识度来自「墨色单色的克制感」与「排版的秩序感」，而非色彩堆叠。

三个设计承诺

克制用色 —— 中性色承担 95% 表达，功能色只在语义必要时出现。
边框优先 —— 用 1px 边框划分层次，阴影只留给浮层。
秩序先于装饰 —— 间距、字号、圆角全部取自 token，无任意值。

明确不做

紫蓝渐变主视觉 · 等权重多彩堆叠 · 装饰性大圆角 · 静态卡片加阴影 · 居中一切 · 纯装饰性 emoji

依据：企业后台对色彩持克制态度（Ant Design）；反 AI-slop 清单（modern-ui-design-audit）。

04 · 间距

基础单位 8px，密集场景可用 4px 半步。禁止任意值 —— 这是消除「同类容器多种内边距」的根本手段。

space-1 · 4px
图标与文字
space-2 · 8px
标签与输入框
space-3 · 12px
同组控件
space-4 · 16px
表单字段之间
space-5 · 20px
表格单元格（水平）
space-6 · 24px
卡片内边距 / 区块间距
space-8 · 32px
页面级区块分隔
邻近性三档：8px 同一信息单元内部 → 16px 相关字段之间 → 24px 不同区块之间。 用间距的倍差划分层级，比加分隔线更轻。

07 · 模式

模式是组件的组合范式。以下为本项目必须统一的三类。

空态 · Empty（三段式）

还没有文章

文章发布后会出现在站点首页和归档中

状态提示 让用户理解为什么空 → 帮助引导 解释价值 → 建议动作 给出下一步。

加载态 · Loading（骨架屏优先）

内容密集页面（列表/卡片/详情）用骨架屏保持布局占位；按钮提交用按钮内 spinner； 轻量局部刷新用内联 spinner。禁止各页写一句「加载中…」文本。

反馈 · Feedback（按场景匹配）

场景反馈方式
成功 · 留在原页Toast（轻量，不打断）
成功 · 跳转行内提示 + 说明
失败 · 需决策对话框（说明问题 + 给出解法）
输入不合规表单字段行内错误
破坏性操作二次确认对话框

08 · 无障碍基线

这是底线要求，不是加分项。当前实现的主要缺口集中在焦点管理与键盘可达。

必须满足

正文对比度≥ 4.5:1
UI 元素 / 大文本≥ 3:1
焦点环2px + offset 2px
触控目标≥ 36px / 移动 44px

焦点样式示意

:focus-visible { outline: 2px solid var(--ring); outline-offset: 2px }
所有可交互元素适用；禁用 outline:none 而不给替代。

键盘走查要点：列表项应为 <button> 而非 div+onClick · 下拉菜单支持 Esc 关闭与方向键 · 抽屉须有焦点陷阱与焦点归还 · 状态不可单靠颜色（配文字或图形）。
