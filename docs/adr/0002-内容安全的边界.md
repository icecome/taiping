# ADR 0002：内容安全的边界

- 状态：已采纳
- 日期：2026-10-26
- 相关：[docs/02-CMS架构设计方案.md](../02-CMS架构设计方案.md) 的 12 节

## 背景

三种可选路线：

| 路线 | 做法 | 问题 |
| --- | --- | --- |
| A. 允许原生 HTML + 消毒 | marked 透传 HTML，用 DOMPurify 消毒 | Workers 没有 `document`，DOMPurify 需要 `jsdom`，包体与冷启动都不可接受 |
| B. 结构化文档 | Tiptap 存 JSON，服务端直接渲染 | 安全，但编辑器与依赖体积大（参考项目 flare-stack-blog 走这条） |
| C. Markdown + 关闭 HTML 透传 | marked 的 `html` 渲染器改为转义 | 作者不能写 HTML |

LuyBlog 的做法是「开 `rehype-raw` 且不消毒」，与「token 存 localStorage」组合成一条完整的攻击链：作者写入恶意 HTML → 访客执行 → 读走同源令牌 → 接管后台。

## 决策

**选 C。** 三处具体规则：

1. **正文**：`lib/markdown.ts` 的 `html` 渲染器返回 `escapeHtml(token.text)`，正文里的 `<script>`、`onerror` 等一律变成可见文本。HTML 完全由渲染器自己拼出，属性值统一走 `escapeHtml`。
2. **评论**：数据库存纯文本，`site/data.ts` 的 `loadComments` 输出前先 `escapeHtml`，再把换行转成 `<br>`。这也与 flare-stack-blog 的 ADR 0011 结论一致。
3. **注入点**：只有两处使用 `dangerouslySetInnerHTML` —— 渲染后的正文，以及插件注入的 `<head>` / 页脚片段。两处都在代码里写明「这里的 html 已在服务端生成并转义」。

## 理由

- 服务端不需要任何依赖 DOM 的消毒库，Worker 包里少一个重量级依赖。
- 攻击面从「所有作者输入」收敛到「渲染器自己拼的模板字符串」，后者可审阅。
- 代价明确：作者不能在正文里写 HTML。需要嵌入视频、图表这类组件的场景留给插件钩子（`content.renderHtml`），插件代码是编译进包的、经过审阅的。

## 后果

- 主题里凡是输出动态文本一律走 JSX 插值，靠 hono/jsx 自动转义。
- `<style>` / `<script>` 这类原始文本元素必须用 `dangerouslySetInnerHTML` 或 `raw()` 插入，否则 `>`、`&` 会被转义导致样式与脚本失效。这是 hono/jsx 的行为，不是 bug。
- 新增任何「允许富文本」的字段（例如自定义字段类型 `markdown`）都必须走同一套渲染函数。

## 验证

`apps/server/src/lib/markdown.test.ts` 有两条直接对应的用例：正文 `<script>` 被转义、`<img onerror>` 不产生可执行属性。
