# 内容域重构设计（方案 A）

> 参考：Typecho 表结构与 slug 策略 + Halo 发布双指针与回收站。  
> 技术栈不变：Cloudflare Worker + D1 + TS monorepo。  
> 范围：文章/页面内容域。说说、评论、媒体、镜像队列保留；鉴权与站点设置后置。

## 1. 目标

1. 草稿与已发布内容分离（改稿不覆盖线上）。
2. 多版本 revision，可查看、可回退（整篇快照，不做 line-diff）。
3. 回收站（逻辑删）+ 彻底删除。
4. slug 生成与校验同源，冲突自动后缀（Typecho 风格）。
5. 与评论 `target_id`、镜像 `entity_id` 的关联保持 `posts.id` 不变。

## 2. 数据模型

```text
posts                     元数据 + 发布指针（Halo）
  id, slug UNIQUE, type(post|page), title
  head_revision_id        最新可编辑正文指针
  release_revision_id     当前线上正文指针（可空）
  status(draft|published)
  deleted_at              回收站（NULL=正常）
  published_at, created_at, updated_at
  template, sort_order
  encrypt, encrypt_*      加密字段仍在 posts

post_revisions            正文整篇快照（Typecho revision 扩展为多条）
  id, post_id → posts ON DELETE CASCADE
  content_md, content_html, excerpt, cover, reading_time
  created_at

terms / post_terms        分类标签（沿用，删除文章时清关系）
```

**不再**把 `content_md/html/excerpt/cover` 放在 `posts` 上；读路径按指针 JOIN `post_revisions`。

## 3. 发布状态机

```text
创建草稿     posts + revision(head)，release=null，status=draft
保存草稿     追加/替换 head 修订；若已有 release 且 head==release，必须新开 revision
发布         release=head，status=published，补 published_at
已发布再存   新 revision=head，release 不变 → inProgress=(head≠release)
再次发布     release=head，inProgress=false
撤下         status=draft（保留 release 指针，便于再发/对照）
回收站       deleted_at=now（前台不可见）
恢复         deleted_at=null
彻底删除     DELETE posts（revisions/post_terms 级联）
回退         将历史 revision 内容复制为新的 head revision
```

前台可见条件：`status='published' AND deleted_at IS NULL AND release_revision_id IS NOT NULL`。

## 4. Slug

- `slugify`：只保留 `[a-z0-9]` 与连字符；空则 `post-<id>`。
- 校验与生成共用 `SLUG_RE`。
- 唯一：DB `UNIQUE(slug)` + 写入时冲突自动 `-1`、`-2`（Typecho）。

## 5. API（内容域）

```text
GET    /api/admin/posts                 列表（status/type/q/deleted）
GET    /api/admin/posts/:id             详情（含 head 正文 + 修订列表摘要）
POST   /api/admin/posts                 创建草稿
PATCH  /api/admin/posts/:id             更新元数据+正文（按状态决定是否新开 revision）
POST   /api/admin/posts/:id/publish     发布（release=head）
POST   /api/admin/posts/:id/unpublish   撤下
POST   /api/admin/posts/:id/recycle     移入回收站
POST   /api/admin/posts/:id/restore     从回收站恢复
DELETE /api/admin/posts/:id             彻底删除
GET    /api/admin/posts/:id/revisions   历史版本
POST   /api/admin/posts/:id/revisions/:revisionId/revert  回退
```

契约层：`PostInput` 仍收 `contentMd` 等，由服务层落到 revision；响应 `Post` 带 `headRevisionId` / `releaseRevisionId` / `inProgress` 及当前 head 内容字段。

## 6. 与保留模块的边界

| 模块 | 约定 |
|---|---|
| 评论 | 继续 `target_type=post` + `target_id=posts.id`；彻底删除时清评论 |
| 镜像 | 仍 `enqueueMirror('post'|'page', id, upsert|delete)` |
| 媒体 | 不感知 revision，封面 URL 存 revision.cover |
| 说说 / 鉴权 / 设置 | 本轮不改结构 |

## 7. 迁移

`0009_content_domain.sql`：

1. 建 `post_revisions`；
2. `posts` 增加 `head_revision_id` / `release_revision_id` / `deleted_at`；
3. 将旧 `content_md/html/excerpt/cover/reading_time` 迁入 revision（id=`rev_mig_<post_id>`）；
4. 回填指针（已发布则 release=head）；
5. 删除 posts 上旧内容列。

无数据时上述 INSERT 为空操作，等价空库初始化。
